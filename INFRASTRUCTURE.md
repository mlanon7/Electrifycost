## Email — ImprovMX forwarding + Gmail "send as"

The site uses **ImprovMX** (improvmx.com) for the `@electrifycost.com` mailbox, paired with Gmail for actually reading and sending.

| Item | Value |
|---|---|
| **Provider** | ImprovMX (improvmx.com) |
| **Primary address** | `martin@electrifycost.com` |
| **Inbound (receiving)** | ImprovMX forwards `@electrifycost.com` mail to the owner's Gmail inbox |
| **Outbound (sending)** | Gmail **"Send mail as"** relays through ImprovMX SMTP — `smtp.improvmx.com`, port `587`, TLS |
| **ImprovMX SMTP credential** | exists for `martin@electrifycost.com` (Premium feature; required for the Gmail send-as relay) |

So mail flows: inbound → ImprovMX → Gmail; outbound → Gmail composes "as `martin@electrifycost.com`" → relays out through `smtp.improvmx.com`. The address is a fully usable sending identity, not just a forwarder.

### Why this matters for the site
The `@electrifycost.com` address is the **outreach channel** for the backlink/authority work that is the site's primary growth lever (a ~1-month-old domain is authority-gated on head terms — see `ROADMAP.md`). Deliverability of that outreach mail is therefore load-bearing, which is why the full SPF + DKIM + DMARC stack below was set up rather than leaving the domain on SPF alone.

## Email authentication — SPF, DKIM, DMARC

All three records live in the Vercel DNS panel. **Verified end-to-end at 10/10 on mail-tester.com on 2026-06-14** ("you're properly authenticated" — SPF, DKIM, and DMARC all passing on a real outbound message).

### 1. SPF (already present from ImprovMX setup)
Authorizes ImprovMX's servers to send for the domain.
```
Type:  TXT
Name:  @  (root)
Value: v=spf1 include:spf.improvmx.com ~all
```

### 2. DKIM (added 2026-06-14)
Two CNAMEs that let ImprovMX cryptographically sign outbound mail as `d=electrifycost.com`. This is what gives a DKIM "pass" that *aligns* with the From address even when mail is relayed/forwarded — SPF alone does not guarantee alignment on relayed mail.
```
Type:  CNAME    Name: dkimprovmx1._domainkey    Value: dkimprovmx1.improvmx.com
Type:  CNAME    Name: dkimprovmx2._domainkey    Value: dkimprovmx2.improvmx.com
```
The selectors chain through to a published `v=DKIM1` public key (verified resolving). DKIM is only needed because the domain **sends** via ImprovMX SMTP; a receive-only forwarder would not require it. Source guide: <https://improvmx.com/guides/adding-dkim-records/>.

### 3. DMARC (added 2026-06-14)
Policy + reporting layer on top of SPF/DKIM. Currently in **monitoring mode** (`p=none`) — watching, not yet quarantining/rejecting spoofers. This is the deliberate safe starting state.
```
Type:  TXT
Name:  _dmarc
Value: v=DMARC1; p=none; rua=mailto:martin@electrifycost.com; fo=1
```
- `p=none` — monitor only (no blocking yet)
- `rua=mailto:martin@electrifycost.com` — aggregate XML reports land in the inbox (no action needed to read them; the policy protects regardless)
- `fo=1` — also generate failure reports

### MX (receiving)
```
MX  10  mx1.improvmx.com
MX  20  mx2.improvmx.com
```

## Verification commands (run any time to confirm records are live)

```bash
# DKIM selectors resolve to ImprovMX, which publishes the v=DKIM1 key
nslookup -type=CNAME dkimprovmx1._domainkey.electrifycost.com 8.8.8.8
nslookup -type=TXT   dkimprovmx1.improvmx.com 8.8.8.8

# DMARC policy
nslookup -type=TXT _dmarc.electrifycost.com 8.8.8.8

# SPF
nslookup -type=TXT electrifycost.com 8.8.8.8
```
End-to-end test (the real proof): send **as** `martin@electrifycost.com` to a unique [mail-tester.com](https://www.mail-tester.com) address (or `check-auth@verifier.port25.com`) and confirm SPF/DKIM/DMARC all pass. **Do not** test by sending Gmail-to-the-same-Gmail — Google delivers it internally and skips inbound authentication, so it shows no auth results (a misleading non-test). See `.claude/lessons/09-email-auth-dmarc-dkim.md`.
